# scripts/deploy-application.sh — despliegue de UN unico artefacto, sin CI/CD.
# (Ejecucion real en vivo la corre Persona 2/Persona 4 con `az login`; ver README.)

$ scripts/deploy-application.sh --help
Uso: scripts/deploy-application.sh [--slot <nombre>] [--artifact <ruta.jar>] [--build] [--swap]

# Flujo tipico: construir el jar y publicarlo en el slot 'staging' (recomendado).
$ scripts/deploy-application.sh --build
[INFO] Parametros validados correctamente.
[INFO] Construyendo artefacto con Maven (skipTests)...
[INFO] Artefacto a desplegar: /home/<user>/Centinela/target/centinela-0.1.0-SNAPSHOT.jar
[INFO] Web App: cent-app-<hash6>
[INFO] Slot destino: staging
[INFO] Publicando artefacto (az webapp deploy --type jar)...
[INFO] Despliegue completado en slot 'staging'.
[INFO] ISS-S1-004 (deploy): artefacto unico publicado sin pipeline CI/CD.

# Si el jar ya existe en target/, se detecta sin --build:
$ scripts/deploy-application.sh --artifact target/centinela-0.1.0-SNAPSHOT.jar

# Promocion staging -> produccion tras validar (swap in-place, mantiene identidad
# y slot settings de cada ambiente):
$ scripts/deploy-application.sh --slot staging --swap
[INFO] Despliegue completado en slot 'staging'.
[INFO] Haciendo swap 'staging' -> produccion...
[INFO] Swap completado: 'staging' es ahora produccion.

# NOTAS:
# - No requiere GitHub Actions ni pipeline. Es un despliegue manual reproducible.
# - Un unico artefacto: se rechaza si hay 0 jars y no se pasa --build/--artifact.
# - El swap conserva los slot settings sticky, por lo que CENTINELA_ENVIRONMENT y
#   los nombres de contenedores/colas NO se intercambian entre ambientes.
